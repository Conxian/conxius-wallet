## 2. Org Sub-Repo Architecture & SDK Boundary Guidance

### Sub-Repo Boundary Definition
- **conxius-wallet (This Repo)**: Tier 1 Production Core client app. Owns UI, native Android managers (`android/core-bitcoin`), client-side protocol services (`services/`), and local enclave storage.
- **lib-conxian-core**: Upstream core cryptographic and protocol libraries. Client application must consume packaged releases rather than modifying sub-project code directly from the wallet repository.
- **conxian-gateway**: Upstream backend event bus and BFF routing infrastructure.
- **conxius-platform**: Sibling full-stack server and cloud blueprint repository. CI failures in `conxius-platform` (CON-1230, CON-1231, CON-1232) are platform-repo baseline issues and do not contaminate local wallet builds.

### SDK Boundary & Agnostic Hardware Surface Guidance
- **Advise Against Local SDK Forking**: Rely on canonical, audited SDK releases (`@noble/curves`, `bitcoinjs-lib`, `liquidjs-lib`, `bdk-android`, BouncyCastle).
- **Native Bridge First**: For performance-critical protocol paths (Ark PRF, Silent Payments scanning, Liquid blinding), leverage native JNI/Kotlin bridges guarded by `ProductionRuntimeGuard` rather than unreviewed TypeScript simulations.
- **Hardware Agnostic SDK Abstraction**: Supports seamless key management across mobile TEE (TrustZone/Secure Enclave), desktop TPM 2.0, institutional HSM (PKCS#11), cloud Server Enclaves (Nitro/SGX), browser FIDO2/Passkeys, and retail POS hardware terminals.
